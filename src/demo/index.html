Inspection receives up to 10 messages with zero visibility timeout and does not delete them. It increments their receive counts and may show the same messages again. The invalid-message button submits one fixed malformed envelope for DLQ handling.

A short presentation route

  1. Create a wallet with 100.00, then submit a 25.00 BET.
  2. Replay: the transaction stays the same and the balance remains 75.00.
  3. Change the amount and send a conflict: expect HTTP 409.
  4. Submit a new 80.00 BET: expect an insufficient-funds rejection.
  5. Read the ledger and reconcile: the difference should be 0.00.

These are interactive HTTP scenarios. The complete suite also tests real SQS delivery, three processes, concurrency and crash recovery.
